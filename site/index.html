How it works

You don’t need to understand any of this to use Cosine. Here it is anyway, for the curious.

Under the hood, every note is built by adding up its harmonics directly — the way a pipe organ or a Hammond does it, not a wavetable and not a stack of separate oscillators. That’s the whole trick: turning up Brightness just changes how loud each harmonic is, all at once, for free.

Σk=1..n rᵏ·cos(2πkp)  =  ( r·c₁ − r² − rn+1·cn+1 + rn+2·cn ) / ( 1 − 2r·c₁ + r² )   ck = cos(2πkp)

Written out, that’s a closed-form sum of cosines — one per harmonic, with a mathematically exact cutoff, so nothing lives above the harmonic you set. That’s the whole reason the oscillator itself can never sound harsh or aliased, no matter how bright you push it:

The one part of that sum that takes any real work stays cheap even at 2000 harmonics, and it’s remembered for as long as you hold a note — which is why the cost never climbs. Full derivation and every measured number, if you want to go deeper: the scientific monograph.

What's in it

A 24-voice synth, laid out the way you actually build a sound.

Oscillator

Brightness sweeps dark-to-bright with zero stepping. Partials caps how many harmonics you hear — great for melting a buzzy tone down into something round and simple, live. Formant adds a resonant, almost vocal peak. Plus band-limited Saw and Triangle for classic analog-style tones.

Character — the dirt, on purpose

Drive, an asymmetric wavefolder, bit-crush and sample-rate reduction. Silky clean at zero, PPG / DX7-style digital grit the moment you push it.

FM

A classic sine-operator FM voice — ratio and amount — plus operator feedback: bell and metallic tones, or push feedback into full-on noise.

Filter & envelopes

A resonant filter (low/band/high-pass, notch) plus a filter envelope that’s completely independent from the amp envelope — a pluck and its filter sweep can move on their own separate clocks. Envelope times are honest: set 1 second, get 1 second.

Voices & unison

24-voice polyphony, and up to 8 voices stacked per note with detune, stereo spread and a slow, natural drift — so big unison pads breathe instead of sitting there static. Flip on HQ mode any time a patch needs extra headroom, for a small, fixed amount of latency.

Microtuning that's in tune with itself

Just intonation, historical tunings, 19/24/31-tone equal temperament, Bohlen-Pierce, or your own Scala file. Because the harmonics sit exactly where the maths says they should, a just-intonation chord actually stops beating — you can hear it lock in. 12-TET stays the untouched default.

Expression

Press one note of a chord harder — MPE, poly aftertouch, channel pressure — and only that note gets brighter. Real per-note expression, not a global filter sweep.

Modulation

A per-voice LFO — sine, triangle or saw, retriggered per note or running free — that can hit brightness, vibrato, filter cutoff or FM depth. Pick one target, or stack a few at once.

Workflow

A live A/B morph slider you can automate for real. A 6-character code that reproduces any random patch exactly — share a sound in a text message instead of a preset file. 22 starting presets to build from.

See what you hear

Watch the real shape of your tone on screen — the harmonic comb and the filter curve, both moving live with your modulation — plus a simple meter that lights up the moment something’s about to sound harsh, so you know exactly when to reach for the cleanup switch.

For developers

The same engine, without the plugin.

Underneath the Cosine plugin (harmonic_synth) is harmonic_core — a no_std, zero-dependency Rust DSP crate with a C ABI. The plugin is one host for it.

  • Zero dependencies, no libm, no allocator. ~14 KB no_std cdylib. Links into firmware as-is.
  • One Voice is plain-old-data (624 bytes, no pointers) — the caller owns the memory, the crate never allocates and never panics on the audio path. Polyphony is the host's policy.
  • Cross-compiles clean to Cortex-M4F/M7 (Daisy Seed), Cortex-M0 (soft-float), RISC-V, AArch64 — and wasm32, where an 8-voice browser demo runs the identical code with note allocation in ~40 lines of JavaScript.
  • Regression-test audio by hash. The determinism contract means a render is reproducible across machines; a shared verify module renders two scripted passes and every target checks them against the same 64-bit values in CI.
  • Verified: 120 core tests (11 an adversarial RT-safety suite — NaN / ±∞ / parameter storms), 34 plugin + 9 licence tests, pluginval --strictness 8, clap-validator 35/35, ARM + wasm bit-exactness under QEMU / Node, all on every push.

What it won't do

Published, not buried. In this market that's the marketing.

  • It’s not infinitely flexible. One knob controls the overall brightness tilt, not each harmonic by hand. If you need to hand-draw a completely custom, wild harmonic curve partial-by-partial, that’s a different (and much slower) kind of synth.
  • The oscillator can’t sound harsh; the effects can. Drive, Fold, Grit, FM and feedback generate real digital edge on purpose when you push them — that’s intentional character. HQ Mode cleans it up for a small, fixed amount of latency.
  • HQ Mode won’t lower your CPU usage. It’s a cleanup switch for the dirt/FM stages, not a performance mode. We say this everywhere so nobody’s surprised.
  • Microtuning retunes the fundamental, not each overtone. Just intonation, historical and equal-division scales all work; true bell inharmonicity or a stretched-piano tuning need a different kind of oscillator.
  • One MIDI channel at a time, a 2048-harmonic ceiling, and a small click if you steal past the 24-voice limit.
  • Real embedded hardware hasn’t been measured yet — it compiles clean and passes every check we can run without a physical board. macOS / Linux builds and an AU version are still on the way.

FAQ

The questions a skeptic asks first.

Will pushing this synth choke my computer?

No. Turning up Brightness or stacking harmonics costs the same CPU whether the tone is a plain sine or a screaming wall of overtones — the whole harmonic stack is computed in one shot instead of one oscillator per harmonic. You’ll never hit a CPU wall just from cranking one knob.

Does it sound harsh or “digital” if I push it hard?

The clean oscillator never can — it’s mathematically incapable of that kind of digital nastiness on its own. Push Drive, Fold, FM or feedback hard enough and yes, those can turn gritty and harsh — that’s intentional character, the same kind PPG and DX7 fans love. The built-in meter tells you the moment it’s happening, and HQ mode cleans it up whenever you don’t want it.

Why doesn’t HQ mode lower my CPU usage?

Because the oscillator was never the expensive part — HQ’s only job is to catch harshness coming from the dirt and FM stages before it reaches your ears, not to make the synth “more efficient.” Turn it on when a patch needs cleaning up, leave it off otherwise; it costs roughly the same CPU either way, plus a small fixed bit of latency while it’s on.

If I freeze or bounce a track, will it still sound right months later?

Yes, always — on this laptop, a different one, a Mac, a PC, even a different buffer size. Cosine renders the exact same audio, every single time, so a freeze from six months ago still sounds identical today. No re-rendering and hoping for the best.

VST3 and CLAP — where’s AU / AAX?

VST3 + CLAP at launch. AU (for Logic users) is planned. AAX (Pro Tools) isn’t — it would require a hardware dongle, and we’re not doing that to you.

Where does the name come from?

Every note is literally built by adding up cosine waves, one per harmonic — that’s the entire trick, no secret sauce hiding underneath. The name just says what it does. The domain’s still being sorted before launch; the plugin itself is finished and already tested.
