## 1. Дефекти сигнального тракту (Критичні виправлення)

### 1.1. Дефект апроксимації `tanh_pade` та паразитарний аліасинг
*   **Локалізація:** `harmonic_core/src/character.rs` (функція `process` та `process_hq`).
*   **Суть проблеми:** 
    Для асиметричного насичення використовується Паде-апроксимація гіперболічного тангенсу:
    $$\text{tanh\_pade}(x) = \frac{x(27 + x^2)}{27 + 9x^2}$$
    У документації та коді зафіксовано жорстке обмеження (clamp) вхідного сигналу $|x| \le 4.0$. 
    Проте математичний аналіз показує, що локальний максимум/мінімум цієї раціональної функції припадає **точно на $x = \pm 3.0$**, де значення дорівнює точно $\pm 1.0$ (перша похідна $f'(3) = 0$). 
    Коли вхідний сигнал `pre` зростає від $3.0$ до $4.0$, функція починає розвертатися вгору (на $x=4.0$ значення дорівнює $1.00585$), після чого примусово обрізається клампом на межі $4.0$.
*   **Наслідок:** 
    У точці клампу $|x| = 4.0$ виникає різкий перелом функції (kink) — миттєвий розрив першої похідної (вона падає з $0.015$ до $0.0$). Цей злам генерує паразитарний високочастотний аліасинг (брудний цифровий писк), повністю руйнуючи аналоговий характер насичення.
*   **Технічне рішення:** 
    Знизити поріг клампування вхідного сигналу `pre` перед обчисленням `tanh_pade` з `4.0` до **точно `3.0`** (тобто `pre.clamp(-3.0, 3.0)`). 
*   **Очікуваний ефект:** 
    При $|x| \le 3.0$ функція плавно досягає асимптоти $\pm 1.0$, її перша та друга похідні на межі дорівнюють точно $0.0$ ($C^2$-безперервність). Це повністю ліквідує перелом функції, роблячи сатурацію ідеально м'якою та вільною від високочастотного бруду навіть у режимі 1× (без HQ).

### 1.2. Транзиєнтний клік та витік звуку в Sample & Hold (S&H)
*   **Локалізація:** `harmonic_core/src/character.rs` (структура `Character` або блок S&H у `voice.rs`).
*   **Суть проблеми:** 
    Модуль пониження частоти дискретизації (downsample) використовує стан `hold` для утримання попереднього значення амплітуди:
    ```rust
    hold_ctr += 1.0;
    if hold_ctr >= factor {
        hold = y;
        hold_ctr -= factor;
    }
    y = hold;
    ```
    Під час вивільнення голосу та нового взяття ноти (Note-on / `Voice::reset()`) внутрішня змінна стану `hold` зберігає останні значення амплітуди з попереднього (вже згаслого) голосу.
*   **Наслідок:** 
    Протягом перших кількох семплів нової ноти (до 15 семплів при максимальному даунсемплі) на вихід подається застарілий сигнал «хвоста» попередньої ноти. Це створює помітний транзиєнтний клік та витік (bleed) звуку на самому початку атаки нової ноти.
*   **Технічне рішення:** 
    У методі `reset()` модуля `voice.rs` (або у внутрішньому `reset` для `Character`) додати примусову ініціалізацію:
    ```rust
    self.character.hold_ctr = 0.0;
    self.character.hold = 0.0; // Або ініціалізувати першим вхідним семплом
    ```

## 2. Потенціал оптимізації CPU (Нові вектори)

### 2.1. Прискорення розрахунку зрізу фільтра `tan_turns` у ~3 рази
*   **Локалізація:** `harmonic_core/src/trig.rs` та `harmonic_core/src/filter.rs`.
*   **Суть проблеми:** 
    Для розрахунку коефіцієнта прогину частоти зрізу $g = \tan(\pi f_c / f_s)$ ZDF SVF-фільтр щосемплово викликає функцію `tan_turns(turns)`. Зараз вона реалізована через важке ділення:
    $$\text{tan\_turns}(turns) = \frac{\text{sin\_turns}(turns)}{\text{cos\_turns}(turns)}$$
    Це змушує процесор розраховувати **два незалежні 8-членні поліноми Тейлора (Горнера)** для синуса й косинуса. Оскільки фільтрова обгинаюча ADSR модулює зріз фільтра посемплово для кожного голосу, цей блок є головною гарячою точкою (bottleneck) всього сигнального тракту.
*   **Аналіз обмежень:** 
    Частота зрізу фільтра жорстко обмежена верхньою межею $0.45 f_s$, тому вхідний аргумент у обертах (turns) ніколи не перевищує $0.225$ (тобто кут $\theta \le 0.45\pi$ рад).
*   **Технічне рішення:** 
    Реалізувати швидку функцію `tan_turns_fast(turns)` на обмеженому інтервалі $[0, 0.225]$ за допомогою **одного прямого мінімаксного раціонального полінома Чебишова** (наприклад, ступеня $[3/2]$ або $[3/3]$):
    $$\tan(\pi x) \approx \frac{x(a_0 + a_1 x^2 + a_2 x^4)}{1.0 + b_1 x^2}$$
    Коефіцієнти розраховуються за алгоритмом Ремеза для мінімізації ULP-похибки на інтервалі $[0, 0.225]$.
*   **Очікуваний ефект:** 
    Замість 16 множень та 2 редукцій аргументу, ми отримуємо всього 4–5 множень, 1 додавання та 1 ділення. Обчислювальна вартість фільтра при активній модуляції cutoff знизиться **приблизно у 3 рази**.

### 2.2. Оптимізація та підвищення точності `exp2`
*   **Локалізація:** `harmonic_core/src/trig.rs` (функція `exp2`).
*   **Суть проблеми:** 
    Поточна функція `exp2` використовує стандартний 8-членний ряд Тейлора, центрований у точці $0$ для дробової частини $f \in [0, 1)$. Через нерівномірний розподіл похибки Тейлора, на межі $f \to 1$ відносна похибка досягає $1.5 \cdot 10^{-6}$ (~2 міліценти). Ми виконуємо 8 операцій множення за схемою Горнера, але втрачаємо точність.
*   **Технічне рішення (два альтернативні шляхи):**
    *   **Шлях А (Максимальна точність):** Замінити поточні коефіцієнти Тейлора на оптимізовані мінімаксні коефіцієнти Чебишова того самого 7-го ступеня для інтервалу $[0, 1]$. Це дасть **майже повну точність `f64` (14 значущих цифр)** без жодного додаткового множення, повністю усуваючи мікро-дрейф висоти при глибоких модуляціях.
    *   **Шлях Б (Максимальна швидкість):** Якщо поточна точність у $10^{-6}$ нас задовольняє, ми можемо замінити 7-й ступінь полінома Чебишова на **4-й ступінь** (5 коефіцієнтів).
*   **Очікуваний ефект:** 
    Шлях Б дозволить **вдвічі знизити CPU-вартість** кожної операції `exp2` по всьому рушію (зміна висоти нот, детюн унісону, згасання ADSR) зі збереженням поточної точності.
