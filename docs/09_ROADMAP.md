# 09 — Що лишилось зробити

Ядро й плагін стабільні: `104/104` тестів, біт-у-біт на `aarch64` + `armv7-hf`
під QEMU, clippy чистий (std / no_std / nightly-simd), VST3 проходить
`pluginval --strictness 8` (з GUI-тестами), CLAP — `clap-validator 35/35`,
плагін має GUI (`nih_plug_vizia`).

Нижче — **тільки незавершене**: активні задачі та свідомо відкладені
напрямки з причиною відкладення. Кожен пункт: **Проблема / Напрямок /
Файли / Чому не зараз**.

## Активне

### В2 — жива DAW-валідація

- **Проблема.** `pluginval` / `clap-validator` покривають контракт хоста, але
  плагін не тестований у живому Ableton / Reaper / Bitwig / Logic / Cubase.
  Окремо: колесо висоти, педаль CC#64, CC#123 та понотна експресія
  (MPE / афтертач → «Expr → Bright») проходять лише за `MIDI_INPUT =
  MidiConfig::MidiCCs` (виставлено) — валідатори цю різницю не ловлять,
  потрібен живий хост / MIDI-контролер.
- **Напрямок.** Ручний прогін `docs/11_DAW_CHECKLIST.md` по ≥ 3 хостах
  (з MPE-контролером хоча б в одному); зафіксовані баги — в issue-трекер.
- **Файли.** `docs/11_DAW_CHECKLIST.md` (протокол) + журнал результатів у ньому.
- **Стан.** Перший прогін у **REAPER 7.79 (CLAP, Windows 11)** зроблено:
  звук / GUI / спектр / пресети / рандомайзер — OK; знайдено й виправлено
  накладання секцій у редакторі (`editor.rs`, деталі — в журналі `docs/11`).
  Лишаються групи `11 §1–5` та інші хости.
- **Чому не завершено.** Решта потребує ручної роботи в кожному DAW
  (state recall із перезапуском, SR-світ, крадіжка голосів, MPE-контролер).

## Відкладено — з причиною

### SoA-SIMD (4–8 голосів паралельно)

- **Напрямок.** Перебудова `render_sample` з AoS на SoA, щоб рахувати
  осцилятори кількох голосів у `f64x4`.
- **Чому не зараз.** Немає CPU-тиску: плагін — 24 голоси, запас `~590×`
  realtime після clean-voice fast path. Вартість — переписати найгарячіший і
  найкритичніший код. Критерій «біт-ідентично скаляру» конфліктує з самим
  сенсом SIMD (контракт детермінізму забороняє FMA / реасоціацію).
  `no_std` не має runtime feature-detection → AVX-512 безпечно не постачити.
  Перший крок, коли дійде: блок-рендер плагіна, не повний AoS→SoA.

### Block-x4 рендер (`render_block` через `geometric_partials_x4`)

- **Напрямок.** Векторний шлях для голого осцилятора в `render_block`.
- **Чому не зараз.** Плагін рендерить посемплово (sample-accurate MIDI), тож
  блок-шлях не на гарячому шляху. Лишається як опція для офлайн /
  `render_block`-споживачів. Батч-версія `geometric_partials_x4` уже є й
  протестована; не інтегрована у `Voice`, бо SVF і character — серійні
  рекурсивні фільтри, які по часу не векторизуються.

### 4× HQ-режим

- **Напрямок.** Опція оверсемплінгу `4×` понад наявний `2×` Unified HQ Bus.
- **Чому не зараз.** `2×` уже дає аліас-підлогу `−94.6` дБ (DoD `−75`); `4×`
  подвоїв би CPU й латентність без доведеної потреби.

### Minimum-phase майстер-дециматор

- **Напрямок.** Замінити 65-тапний лінійно-фазовий FIR на minimum-phase (нижча
  латентність).
- **Чому ні.** Лінійно-фазові `16` семплів (`~0.36` мс @ 44.1k) компенсуються
  PDC і не відчутні. Minimum-phase дав би нелінійно-фазове розмиття у верхньому
  спектрі — саме той дефект, який прозорість адитивного синтезу має уникати.

### Компенсація ВЧ-спаду PolyBLEP

- **Проблема.** Пилка / трикутник трохи спадають на `f₀ > 3` кГц (`−0.11` дБ
  на 3 кГц).
- **Чому ні (латка).** 1-полюсний high-shelf повернув би стан у stateless-
  генератор — руйнує сам сенс PolyBLEP. Спад `< 0.11` дБ до 1 кГц —
  психоакустично непомітний.
- **Напрямок, якщо знадобиться.** Безстанове BLEP-ядро вищого порядку
  (2-точкове або B-spline), не фільтр-латка.

### Друге геометричне ядро — базове зроблено

- **Зроблено.** Ручка «Formant» (`04 §0.2`): другий закритий член
  `Σ(aᵏ−bᵏ)cos` додає **один** керований резонансний горб, `Θ(log n)`,
  `formant = 0` побайтово тотожний. `kernel::geometric_hump_pre`.
- **Що лишилось (відкладено).** Кілька формант / гребінчаста обгинаюча (кожен
  член ≈ ще одна `geometric_partials_pre` пара, `Θ(k·log n)`); двонахиловий
  режим (два незалежних `r` замість горба). А також **інгармонічне ядро** —
  сума з не-єдиним відношенням між парціалами (`Σ rᵏcos(2π(c + k·m)p)`, DSF
  Moorer 1976 з `m ≠ c`) для дзвонів / розтягнутих спектрів: це та єдина
  частина «гармонічного замку до строю» (field-notes #1), якої немає у
  мікротюнінгу (`07 §20`). Робити — коли з'явиться конкретна потреба, якої не
  покриває нахил + один горб + фільтр + мікротюнінг фундаменталів.

### `.kbm` мапінг та MTS-ESP — відкладено

- **Зроблено.** Ядро `Tuning` приймає довільну регулярну шкалу; плагін дає
  8 вбудованих шкал + **імпорт `.scl`** (шлях або вставлений вміст, відношення
  й центи, до 64 ступенів; `#[persist]`, `try_lock` в `process`, парс без
  алокацій — `05 §3` / `07 §20`).
- **Що лишилось.** `.kbm` (мапінг клавіатури: зараз лінійний від тоніки, `.kbm`
  дав би довільне розкладання ступенів по клавішах) і клієнт **MTS-ESP**
  (master-tuning від Surge / Oddsound) — обидва суто на рівні `harmonic_synth`.
  MTS-ESP тягне зовнішню бібліотеку → окреме рішення про залежність плагіна.
  Робити — коли мікротональна аудиторія попросить конкретно.

### Розширення C-ABI до `harmonic_poly_*`

- **Проблема.** C-ABI покриває лише один `Voice`; embedded/C-інтегратору,
  якому потрібна поліфонія, доводиться самому писати voice-stealing, унісон
  і (для анти-аліасингу майстра) 65-тапний дециматор поверх масиву `Voice`.
- **Чому ні зараз.** Межа `no_std`-ядра завжди була на рівні одного голосу;
  поліфонічна політика — рішення хоста, не бібліотеки. Розширювати — коли
  з'явиться реальний embedded-запит.

### Залізо: реальний Cortex-M, `thumbv6m` (M0 soft-float), RISC-V

- **Стан.** Крос-компілюється чисто під усі; біт-у-біт **виміряно** лише на
  `aarch64` + `armv7-hf` (VFP `f64` = Cortex-M4F) під QEMU.
- **Не покрито.** Реальне залізо; `thumbv6m` (програмний `f64` — інший шлях
  округлення можливий); прогін під RISC-V.

### Полиш GUI

- **Стан.** GUI мінімальний: заголовок + рядок пресетів (`◀ ім'я ▶`,
  22 стартові, `05 §3`) + спектр-дисплей (виміряні бари **+ гребінка партіалів
  закритої форми** поточного патча — `03 §GUI`, field-notes #2) + чесний метр
  аліасингу (`04 §1.8`) + рядок A/B-морфу (`07 §18`) + рядок seed-рандомайзера
  (`07 §19`) + рядок Scala-імпорту + згруповані секції параметрів (8 секцій —
  TONE / AMP ENVELOPE / CHARACTER / FM / FILTER / VOICE / TUNING / MODULATION)
  у `ScrollView` (замість плоского `GenericUi`).
- **Зроблено (частково).** «Розбери цей пресет» для п'яти контролів:
  наведення на Brightness / Partials / Formant → бліді криві розгортки
  гребінки; на Cutoff / Resonance → те саме для кривої фільтра
  (`03 §GUI`, `b21d8b5`-серія). **Крива відгуку фільтра** на тих самих осях,
  що й гребінка (аналітична АЧХ `Svf`, не окремий графік — оверлей, як у
  Serum/Vital; `03 §GUI`). **Гребінка унісону** — кожен партіал розмазаний на
  сталу ширину в log-f, бліда смуга за центральною гребінкою (`03 §GUI`).
- **Напрямок.** Розширити hover на решту (Drive/Fold/FM — важче, вони аліасять),
  анімувати дрейф унісону / рух LFO (статичну ширину вже видно).
  Ручки замість слайдерів — коли дійде до візуального брендингу. Пресети:
  розширити банк за наслухом (стартові 22 побудовані «по конструкції»,
  верифіковані на обмеженість/тилт, але не докрутовані на слух), пресет-браузер
  з категоріями. Для морфу: винятки по параметрах (не плавити дискретні),
  морф-пад X/Y на 4 знімки. Для рандому: «chaos»-ручка, теги патчів.

### Property-based fuzzer

- **Стан.** Ворожий набір `tests/stress.rs` (`06 §5.2`) покриває RT-safety
  детерміновано: `NaN`/`±∞` у кожен публічний сеттер, шторми, крайні режими,
  2 M семплів. Знайшов і закрив 6 місць.
- **Напрямок.** `cargo-fuzz` / `proptest` — рандомізований пошук замість
  скриптованих сценаріїв; ганяти на послідовностях `{note event, param set,
  render}` проти інваріантів «скінченне, обмежене, пул відновлюється».
- **Чому не зараз.** Детермінованого набору вистачає для наявного периметра
  API; фазер має сенс, коли API розшириться (напр. C-ABI поліфонія) або
  з'явиться CI, щоб ганяти його довго.

### CI-матриця

- **Напрямок.** `.github/workflows`: `cargo test` (вкл. `tests/stress.rs`) +
  clippy (3 конфіги) + `cross-verify.sh` (Docker+QEMU ARM) + `cargo xtask
  validate` на кожен push.
- **Чому не зараз.** Немає CI-інфраструктури; усе проганяється локально.
