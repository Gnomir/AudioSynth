## Вектор А — Розширення DSP та звукового потенціалу

Осцилятор зараз дає лише band-limited імпульсний потік (`D_n`) та його
геометрично-спадні версії (`S_n`). Для конкуренції з флагманами потрібні
класичні хвилі й глибша модуляція.

### А1. Класичні хвилі без аліасингу — leaky-integrated BLIT ✅ ВИКОНАНО

- **Проблема.** `Σ sin(kx)/k` (пила) не має елементарної закритої форми
  (функція Клаузена) — прямий геометричний ряд пилу/трикутник не дає.
- **Рішення.** Leaky-integrated BLIT (Stilson & Smith, 1996): `dirichlet_blit`
  — це вже band-limited імпульсний потік; інтегруємо його з витоком і
  нульовим середнім → **пила**; для **трикутника** — біполярний BLIT
  (`+` у фазі 0, `−` у ½), структурно нульового середнього, два інтегратори.
  Складність лишається Θ(log n) на семпл.
- **Реалізовано.** `voice.rs::blit_saw` / `blit_triangle` + `Waveform` enum
  (`Geometric` / `Saw` / `Triangle`), 6 полів стану на голос; `poly.rs`
  (fan-out + trigger), `lib.rs` re-export, `ffi.rs`
  (`harmonic_voice_set_waveform`), `harmonic_synth/src/lib.rs` (`OscKind`
  EnumParam «Oscillator»), C-header. Docs 01 §7 / 04 §11 / 05 / 07 §6.
- **Результат (виміряно, `f₀ ∈ [27.5, 7040]` Гц).** Пила: спектр `1/k`
  (`h₂ 0.50`, `h₃ 0.33`, `h₄ 0.25`), `≈ ±0.9`, залишок над Найквістом
  `< 0.03 %`. Трикутник: непарні `1/k²` (`h₃ ≈ 1/9`, `h₅ ≈ 1/25`), парні
  `< 1.5 %`, `≈ ±0.45`, DC `≈ 0`, стабільний на 10 с безперервного рендеру.
- **Компроміси (задокументовано, 07 §6).** BLIT не band-limited точно
  (залишок `< 2 %·h₁`); трикутник має спад баса нижче ~80 Гц (`−1.5 дБ` на
  55 Гц) — ціна витоку 2-ї стадії проти втечі подвійного інтегратора;
  завищений `h₃` на `f₀ > 3.5` кГц (`n ≤ 3`). Ігнорують `rolloff` та HQ.
- **Тест.** `voice::blit_saw_and_triangle_are_bounded_and_shaped` на
  `f₀ ∈ {55, 220, 3000}`.
- **Не зроблено.** Демо-WAV (окремим кроком за потреби); polyBLEP-варіант
  трикутника без спаду баса — можливий майбутній апгрейд.

### А2. Поголосна LFO — retrigger + матриця модуляції

- **Проблема.** LFO хоч і поголосний фізично, але не має режиму key-sync
  retrigger vs free-run, і роутиться лише в `rolloff` та `pitch`.
- **Рішення.** (1) `LfoMode { Retrigger, FreeRun }` — у free-run фаза не
  скидається на note-on (аналог `free_running` осцилятора). (2) Розширити
  роутинг: LFO → cutoff SVF (± октави), LFO → FM index. Це просто ще два
  `lfo_to_*` поля + застосування в `render_sample`.
- **Файли.** `lfo.rs` (mode), `voice.rs` (нові цілі), `poly.rs`, плагін
  (2 параметри: LFO → Cutoff, LFO → FM; enum LFO Mode).
- **Оцінка.** S (≈ 2–3 год).
- **DoD.** Тести на обмеженість + що free-run фаза переживає note-on. Docs 04.

### А3. Стерео-унісон — мікро-затримки + динамічна декореляція

- **Проблема.** Унісон робить статичне розстроювання + панораму; стерео-образ
  «правильний», але не «живий».
- **Рішення.** (1) Мікро-затримка на голос унісону (0–20 мс, невеликий
  фіксований делей-буфер на голос АБО спільний пул). (2) Повільний
  незалежний LFO дрейфу фази/детюну на кожен унісон-голос → образ «дихає».
- **Файли.** `poly.rs` (делей-лінії у `PolyVoice`, drift-LFO), плагін
  (Uni Delay, Uni Drift).
- **Оцінка.** M. Ризик: делей-буфери збільшують `PolyVoice` (RAM-бюджет —
  див. `08 §2.3`).
- **DoD.** Ширина стерео вимірювано зростає й **модулюється в часі** (не
  константа). Docs 04.

## Вектор Б — Системна оптимізація та портування

### Б1. «Clean Voice Fast Path»

- **Проблема.** Навіть коли `character = CLEAN`, `filter = Bypass`,
  `fm_index = 0`, `feedback = 0` — `render_sample` усе одно робить per-sample
  перевірки в `character.process` / `filter.process` і тикає LFO, навіть
  нероутований.
- **Рішення.** У `Voice::render_sample` — рання гілка: якщо голос
  провабельно pass-through, пропустити виклики `character`/`filter` цілком і
  тик LFO (коли `lfo_to_* == 0`). Довший приз — `render_block`, що детектує
  «весь блок чистий» і рендерить осцилятор через `geometric_partials_x4`
  (авто-векторизація).
- **Файли.** `voice.rs`, можливо `poly.rs` (block fast-path).
- **Оцінка.** S для per-sample гілки; M для block-x4.
- **DoD.** Бенчмарк: чистий голос **виміряно** швидший (ціль: +20–40 %
  поліфонії). Регресія: driven-голос без змін; вихід біт-у-біт той самий,
  коли гілка не спрацьовує. Оновити `06 §3`.

### Б2. Внесок в upstream — фікс CLAP-обгортки nih-plug

- **Проблема.** `src/wrapper/clap/wrapper.rs` (rev `de421011`):
  (1) `ext_state_load` викликає `set_state_inner` напряму, **не постить**
  `Task::RescanParamValues` → хост не знає про зміну параметрів після `load`;
  (2) `Vec::with_capacity(length as usize)` з невалідованим `length` зі
  стріму → OOM-abort на пошкодженому пресеті (`state-invalid-random`).
  VST3-шлях стану проходить `pluginval` — тобто це саме CLAP-обгортка.
- **Рішення.** Чесний баг-репорт + PR: (1) додати `schedule_gui(
  Task::RescanParamValues)` після `set_state_inner` у `ext_state_load`;
  (2) обмежити `length` розумною межею (напр. 16 МБ) до алокації.
- **Файли.** (upstream) `nih-plug/src/wrapper/clap/wrapper.rs`. Локально —
  тимчасовий `[patch]` на форк, поки PR не змержено.
- **Оцінка.** S (патч тривіальний) + невизначений час на review.
- **DoD.** PR відкрито; після мержу — прибрати `--exclude` зі
  `scripts/validate.*` і `[patch]`; `clap-validator` 35/35.

### Б3. Фізична верифікація на залізі

- **Проблема.** Бітова ідентичність `no_std`-коду поза x86_64 — очікувана
  гіпотеза (`08 §3`), ядро жодного разу не збиралось під ARM/RISC-V.
- **Рішення.** Крок 1 (зроблено, §нижче): крос-**компіляція** під
  `thumbv7em-none-eabihf` (Cortex-M4F), `aarch64-unknown-none`,
  `riscv32imac-unknown-none-elf`. Крок 2: прогін тестів на реальному
  Cortex-M / Apple Silicon (QEMU або залізо), порівняння результатів синтезу
  з x86-еталоном bit-for-bit через C-ABI + статичну `.a`.
- **Файли.** CI-матрицю (`.github/workflows` — коли буде CI), тестовий
  харнес на цільовій платі.
- **Оцінка.** S для крос-компіляції; L для прогону на залізі.
- **DoD.** `cargo build --target …` зелений для 3 таргетів (крок 1).
  Bit-exact порівняння синтезу на ≥1 не-x86 (крок 2) → зняти застереження
  в `08 §3` / `07 §6`.

## Вектор В — Комерційний інтерфейс, жива валідація, продуктивність

### В1. Мінімальний GUI (`nih_plug_vizia`)

- **Проблема.** Плагін — сухий табличний список параметрів хоста. Неприйнятно
  для комерційного релізу.
- **Рішення.** `nih_plug_vizia`: слайдери обох ADSR, крива фільтра,
  ручка Brightness, живий спектроаналізатор виходу.
- **Файли.** `harmonic_synth/Cargo.toml` (+`nih_plug_vizia`, важкі
  залежності — baseview тощо), новий `harmonic_synth/src/editor.rs`.
- **Оцінка.** L. Ризик: `vizia` тягне багато залежностей і подовжує збірку;
  суперечить духу «zero-dependency» (але це плагін, не `harmonic_core`).
- **DoD.** GUI відкривається в DAW, керує всіма параметрами, спектроаналізатор
  оновлюється; `pluginval` без `--skip-gui-tests` проходить.

### В2. Стрес-тест у живих DAW

- **Проблема.** `pluginval` ✔, але плагін не запускався в реальному
  Ableton / Reaper / Logic / Bitwig / Cubase.
- **Рішення.** Ручний чек-лист по кожному хосту: state recall у межах проєкту,
  синхронізація темпу (коли додамо tempo-sync LFO), зміна буфера на льоту під
  час відтворення, автоматизація, кілька інстансів, sample-rate проєкту.
- **Файли.** `docs/` чек-лист + журнал результатів.
- **Оцінка.** M (ручна робота).
- **DoD.** Чистий журнал по ≥3 хостах; зафіксовані баги — в issue-трекер.

### В3. Довготривалий числовий дрейф

- **Проблема.** Фазова математика в обертах, wrap щоперіоду — накопичення
  похибки обмежене теоретично (`07`), але не виміряне на годинах.
- **Рішення.** Стрес-тест: безперервний рендер голосу 12 год (або
  прискорено — 10⁹+ семплів), FFT вихідного хвоста, аналіз на дрейф частоти /
  фазові спотворення. Також перевірити `fm_phase` акумулятор (росте як
  `ratio·step`, wrap через `floor_f64`).
- **Файли.** `harmonic_core/examples/drift_stress.rs` або `tests/`.
- **Оцінка.** S (написати) + час прогону.
- **DoD.** Виміряний дрейф частоти `< X ppm` за N годин; результат у `06`.
