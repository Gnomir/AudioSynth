# 09 — Що лишилось зробити

Ядро й плагін стабільні: `70/70` тестів, біт-у-біт на `aarch64` + `armv7-hf`
під QEMU, clippy чистий (std / no_std / nightly-simd), VST3 проходить
`pluginval --strictness 8` (з GUI-тестами), CLAP — `clap-validator 35/35`,
плагін має GUI (`nih_plug_vizia`).

Нижче — **тільки незавершене**: активні задачі та свідомо відкладені
напрямки з причиною відкладення. Кожен пункт: **Проблема / Напрямок /
Файли / Чому не зараз**.

---

## Активне

### В2 — жива DAW-валідація

- **Проблема.** `pluginval` / `clap-validator` покривають контракт хоста, але
  плагін не тестований у живому Ableton / Reaper / Bitwig / Logic / Cubase.
- **Напрямок.** Ручний прогін `docs/11_DAW_CHECKLIST.md` по ≥ 3 хостах;
  зафіксовані баги — в issue-трекер.
- **Файли.** `docs/11_DAW_CHECKLIST.md` (протокол) + журнал результатів у ньому.
- **Чому не зараз.** Потребує ручної роботи в кожному DAW; автоматизувати
  неможливо.

### Б2 — публічний upstream-PR по фіксу nih-plug

- **Проблема.** Фікс двох багів CLAP-обгортки nih-plug (`ext_state_load`:
  немає `rescan` після `load`; `Vec::with_capacity` на невалідованій довжині
  → alloc-abort) застосований локально через `[patch]` на
  `harmonic_synth/vendor/nih-plug/`. Готовий патч — `contrib/nih-plug-
  clap-state-load-fix.patch` (застосовується на `de421011` і `master`).
- **Напрямок.** Форк `robbert-vdh/nih-plug`, PR, потім `[patch]` на форк
  замість vendored-копії, поки не змержать.
- **Чому не зараз.** Рішення про публічний PR — за користувачем. Деталі:
  `docs/10_NIH_PLUG_CLAP_BUGS.md`.
- **Після мержу upstream:** видалити `harmonic_synth/vendor/nih-plug/` +
  `[patch]`-секцію, бампнути `rev` у `harmonic_synth/Cargo.toml`, прибрати
  рядок `vendor/** -text` з `.gitattributes`.

## Відкладено — з причиною

### SoA-SIMD (4–8 голосів паралельно)

- **Напрямок.** Перебудова `render_sample` з AoS на SoA, щоб рахувати
  осцилятори кількох голосів у `f64x4`.
- **Чому не зараз.** Немає CPU-тиску: плагін — 24 голоси, запас `~590×`
  realtime після clean-voice fast path. Вартість — переписати найгарячіший і
  найкритичніший код. Критерій «біт-ідентично скаляру» конфліктує з самим
  сенсом SIMD (контракт детермінізму забороняє FMA / реасоціацію).
  `no_std` не має runtime feature-detection → AVX-512 безпечно не постачити.
  Перший крок, коли дійде: блок-рендер плагіна, не повний AoS→SoA.

### Block-x4 рендер (`render_block` через `geometric_partials_x4`)

- **Напрямок.** Векторний шлях для голого осцилятора в `render_block`.
- **Чому не зараз.** Плагін рендерить посемплово (sample-accurate MIDI), тож
  блок-шлях не на гарячому шляху. Лишається як опція для офлайн /
  `render_block`-споживачів. Батч-версія `geometric_partials_x4` уже є й
  протестована; не інтегрована у `Voice`, бо SVF і character — серійні
  рекурсивні фільтри, які по часу не векторизуються.

### 4× HQ-режим

- **Напрямок.** Опція оверсемплінгу `4×` понад наявний `2×` Unified HQ Bus.
- **Чому не зараз.** `2×` уже дає аліас-підлогу `−94.6` дБ (DoD `−75`); `4×`
  подвоїв би CPU й латентність без доведеної потреби.

### Minimum-phase майстер-дециматор

- **Напрямок.** Замінити 65-тапний лінійно-фазовий FIR на minimum-phase (нижча
  латентність).
- **Чому ні.** Лінійно-фазові `16` семплів (`~0.36` мс @ 44.1k) компенсуються
  PDC і не відчутні. Minimum-phase дав би нелінійно-фазове розмиття у верхньому
  спектрі — саме той дефект, який прозорість адитивного синтезу має уникати.

### Компенсація ВЧ-спаду PolyBLEP

- **Проблема.** Пилка / трикутник трохи спадають на `f₀ > 3` кГц (`−0.11` дБ
  на 3 кГц).
- **Чому ні (латка).** 1-полюсний high-shelf повернув би стан у stateless-
  генератор — руйнує сам сенс PolyBLEP. Спад `< 0.11` дБ до 1 кГц —
  психоакустично непомітний.
- **Напрямок, якщо знадобиться.** Безстанове BLEP-ядро вищого порядку
  (2-точкове або B-spline), не фільтр-латка.

### Друге геометричне ядро

- **Проблема.** Форма спектра фіксована `rᵏ` — сталий нахил у дБ/гармоніку.
  Резонансний горб чи форманту цією ручкою не отримати (`07 §4`).
- **Напрямок.** Друга закрита геометрична сума з іншим `r` / зсувом →
  керована двонахилова або горбата обгинаюча, все ще `Θ(log n)`.

### Розширення C-ABI до `harmonic_poly_*`

- **Проблема.** C-ABI покриває лише один `Voice`; embedded/C-інтегратору,
  якому потрібна поліфонія, доводиться самому писати voice-stealing, унісон
  і (для анти-аліасингу майстра) 65-тапний дециматор поверх масиву `Voice`.
- **Чому ні зараз.** Межа `no_std`-ядра завжди була на рівні одного голосу;
  поліфонічна політика — рішення хоста, не бібліотеки. Розширювати — коли
  з'явиться реальний embedded-запит.

### Залізо: реальний Cortex-M, `thumbv6m` (M0 soft-float), RISC-V

- **Стан.** Крос-компілюється чисто під усі; біт-у-біт **виміряно** лише на
  `aarch64` + `armv7-hf` (VFP `f64` = Cortex-M4F) під QEMU.
- **Не покрито.** Реальне залізо; `thumbv6m` (програмний `f64` — інший шлях
  округлення можливий); прогін під RISC-V.

### Полиш GUI

- **Стан.** GUI мінімальний: заголовок + спектр-дисплей + `GenericUi`
  (табличний список усіх параметрів) у `ScrollView`.
- **Напрямок.** Власний згрупований layout, крива фільтра окремим графіком,
  ручки замість слайдерів — коли дійде до візуального брендингу.

### CI-матриця

- **Напрямок.** `.github/workflows`: `cargo test` + clippy (3 конфіги) +
  `cross-verify.sh` (Docker+QEMU ARM) + `cargo xtask validate` на кожен push.
- **Чому не зараз.** Немає CI-інфраструктури; усе проганяється локально.
