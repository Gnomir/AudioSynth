# 08 — Інтеграція `harmonic_core` у вбудовані системи

Регламент інтеграції рушія в хост на C/C++ або в RTOS: контракт середовища,
**точний** макет пам'яті, протокол C-ABI, збірка під ціль, і **чесний**
перелік того, що гарантовано, а що ні.

Загальна архітектура — `03_ARCHITECTURE.md`; математика — `01`, `02`; межі —
`07_LIMITATIONS.md`.

---

## 1. Контракт середовища (`#![no_std]`)

| Гарантія | Механізм | Верифікація |
|---|---|---|
| Нуль динамічної алокації | немає глобального алокатора; `Box`/`Vec`/`String`/`format!` відсутні у не-тестовому коді | `grep` (`06_VERIFICATION.md §5`); `assert_process_allocs` у тестовому плагіні |
| Нуль `libm` / системної математики | `sin`/`cos`/`exp2`/`tan`/`floor` реалізовані в `trig.rs` з `+ − × ÷` та `to_bits`/`from_bits` | `02_NUMERICAL_METHODS.md` |
| Нуль паніки в аудіо-шляху | немає `unwrap`/`expect`/`panic!`; усі ділення захищені за побудовою; `[profile.release] panic = "abort"` | `grep`; §5 нижче |
| Нуль блокувань / I/O / часу | у `render_sample` немає `Mutex`, syscall, файлів | огляд коду |

`panic = "abort"` → немає розкрутки стека → менший бінарник, простіша
верифікація безпеки. `#![no_std]`-збірка **лише в `--release`** (dev-профіль
потребує `eh_personality`).

## 2. Макет пам'яті

### 2.1. `Voice` — POD, `#[repr(C)] Copy`

```
size_of::<Voice>()  = 512 байти     (x86-64; те саме на 64-бітних ARM)
align_of::<Voice>() = 8
```

> **Не хардкодьте це число в коді хоста.** Викликайте `harmonic_voice_size()`
> / `harmonic_voice_align()` у рантаймі — розмір зростав із розвитком рушія
> (LFO, панорама, FM, pitch bend) і зростатиме далі. Хардкод `200` зі старої
> документації спричинив би `ptr.write()` за межі виділеного буфера →
> руйнування пам'яті й жорсткий crash.

### 2.2. Повний перелік полів

`Voice` не має внутрішніх вказівників → безпечний для побітового копіювання
та серіалізації стану.

| Група | Поля | Тип | Призначення |
|---|---|---|---|
| Ядро | `sample_rate` | `f64` | Частота дискретизації (клампиться в `[8k, 768k]`) |
| Осцилятор | `phase` | `f64` | Фаза несучої, оберти `[0,1)` |
| | `freq`, `freq_z` | `f64` | Основна частота: ціль / згладжено (~5 мс) |
| | `rolloff`, `rolloff_z` | `f64` | Спектральний нахил `r`: ціль / згладжено |
| | `gain`, `smooth_coeff` | `f64` | Вихідний гейн; коефіцієнт згладжувача |
| Pitch bend | `bend`, `bend_z` | `f64` | Множник висоти `2^(st/12)`: ціль / згладжено (~5 мс) |
| Панорама | `pan`, `pan_z`, `pan_smooth` | `f64` | Equal-power `[−1,1]`: ціль / згладжено (~10 мс) / коеф. |
| | `pan_cache_z`, `pan_sin`, `pan_cos` | `f64` | Кеш equal-power гейнів: `sin_cos` рахується лише коли `pan_z` рухається |
| Старт ноти | `free_running` | `bool` | `true` = фаза переживає note-on |
| | `declick` | `u16` | Лічильник 16-семплового fade-in |
| FM | `fm_phase`, `fm_ratio`, `fm_index` | `f64` | Фаза / відношення / глибина модулятора |
| | `feedback`, `last_osc` | `f64` | Самофідбек оператора + попередній семпл осцилятора |
| LFO | `lfo` | `Lfo` (2×`f64` + `LfoShape` + `LfoMode`) | модулятор; `LfoMode` = Retrigger / FreeRun (key-sync) |
| | `lfo_to_rolloff`, `lfo_to_pitch` | `f64` | Роутинг → яскравість (±) / вібрато (центи) |
| | `lfo_to_cutoff`, `lfo_to_fm` | `f64` | Роутинг → cutoff SVF (± октави) / FM index (±) |
| | `filter_cutoff` | `f64` | Остання база cutoff від хоста — база для `lfo_to_cutoff` |
| Дрейф унісону | `drift_phase`, `drift_inc`, `drift_depth` | `f64` | Повільна вільна синусоїда `→` фаза осцилятора («дихання» стеку); не ретригериться |
| Geom-кеш | `geom_r`, `geom_rn1`, `geom_peak` | `f64` | `r^{n+1}` та пік для сталого `(r, n)` — обидва `powi_pos` пропускаються |
| | `geom_n` | `u32` | друга половина ключа кешу |
| Осц. форма | `waveform` | `Waveform` (`u32`) | Geometric / Saw / Triangle — Saw/Triangle це PolyBLEP/PolyBLAMP, **без стану** |
| Нелінійні | `character` | `Character` | drive / bias / fold / crush / downsample |
| | `filter` | `Svf` (112 б) | ZDF state-variable фільтр |

**Типи всередині нелінійних блоків — навмисний вибір:**

- **`Svf` — увесь стан `f64`.** Інтегратори `ic1`, `ic2` та коефіцієнти
  `g`, `k`, `a1..a3`, `cutoff_z`, `res_z` — `f64`, бо на низьких частотах
  зрізу `f32` накопичує критичну похибку в рекурсії. `f32` діє **лише** на
  межі `Svf::process(x: f32) -> f32`.
- **`Character` — увесь стан `f32`.** `CharParams` (5×`f32`) + DC-blocker
  (`dc_x1`, `dc_y1`) + sample&hold (`hold`, `hold_ctr`) — `f32` достатньо
  (нелінійність не має «довгої» рекурсії за станом).

### 2.3. RAM-бюджет

Один голос — 512 б. Плагін `harmonic_synth` тримає `PolySynth<24>`: масив із
24 `PolyVoice` (`Voice` + дві `Adsr` + метадані нот), ~14 КБ, статично, без
жодної алокації понад те, що розмістив хост. Для MCU обирайте кількість
голосів під свій RAM.

## 3. Обчислювальний детермінізм

Уся математика — в домені **обертів** (1 оберт = 2π рад), що спрощує
діапазонну редукцію.

- **Тригонометрія:** поліноми Горнера (ряд Тейлора до `φ¹⁶`/`φ¹⁷`),
  plain-`a*x + b` **без `mul_add`** — щоб компілятор не контрактив вираз у
  FMA (інакше результат залежав би від апаратної підтримки FMA на таргеті).
  Абсолютна похибка `< 2·10⁻¹¹`.
- **Редукція аргументу — скалярний шлях** (`cos_turns`, який працює в тракті
  голосу): `round_int(x)` = `(x as i64) as f64` + піврегулювання →
  **round-half-away-from-zero**.
- **`exp2`, `floor_f64`:** пряма маніпуляція полем експоненти IEEE-754.
  `exp2` — відносна похибка `< 2.2·10⁻⁸` (Remez мінімакс; `~3·10⁻⁵` цента).
- **Магічна константа `1.5·2⁵²`** (round-half-to-**even**) — це `round_bias`,
  і вона **виключно** всередині `cos_turns_branchless`, який **не бере участі
  в активному рендерингу голосу** (див. §4). У скалярному шляху її немає.

### Платформна ідентичність — верифікована на ARM (RFC-15)

Rust за замовчуванням не контрактить `a*b + c` у FMA; `mul_add` навмисно
уникнуто; x86-64 використовує SSE2 (без 80-бітної розширеної точності);
касти `(x as i64)` насичувані й детерміновані на рівні мови. Тому результат
синтезу мав би бути бітово ідентичним між x86-64 та ARM / RISC-V — і для ARM
**це тепер виміряно, а не гіпотеза**.

Усі 70 тестів ядра (включно з `cross_platform_bit_exact`, який рендерить
100 мс через весь тракт — унісон + drift + FM + feedback + 4 маршрути LFO +
резонансний SVF + усі стадії `Character` — і згортає біти кожного семпла в
хеш) проходять під QEMU на:

- **`aarch64-unknown-linux-gnu`** — 64-бітний ARM;
- **`armv7-unknown-linux-gnueabihf`** — 32-бітний ARM hard-float; набір
  інструкцій VFP для `f64` **тотожний** `thumbv7em-none-eabihf` (Cortex-M4F),
  тож прохід переноситься на bare-metal firmware-таргет.

Хеш вихідного сигналу **збігається біт-у-біт** із референсом, знятим на
`x86_64-pc-windows-msvc` (дельта `= 0.0`). Дрейф фазового акумулятора теж
збігається до останньої цифри (`4.566·10⁻¹⁰` обертів на `2·10⁷` семплів на
всіх трьох архітектурах). Прогін: `scripts/cross-verify.sh` (Docker + QEMU;
`06_VERIFICATION.md §6`).

**Ще не покрито:** реальне залізо Cortex-M (лише емуляція), `thumbv6m`
(M0, без FPU — програмний `f64`; збирається чисто, але не проганявся),
RISC-V прогін (крос-компілюється чисто).

## 4. Продуктивність і векторизація

- **Складність — Θ(log n)** на семпл **на зміні `(r, n)`**: `powi_pos` для
  `r^{n+1}`, `r^n` — `≤ 22` множення при `n ≤ 2048. На **сталій** ноті
  (`clean fast path`) обидва кешуються → фактична вартість **Θ(1)** і плоска
  по `n`. Вимірювано ~26 M семплів/с на голос (скаляр, x86-64), плоско
  3↔1200 гармонік; повний акорд на 64 голоси — ~590 голосів realtime-запасу
  (проти ~330 до fast path). LFO та панорама рахуються 4-членними ядрами
  (`*_fast`, ~16 біт) і пропускаються коли не потрібні; несуча й FM —
  повноточні. Деталі — `06_VERIFICATION.md §3`.
- **HQ mode** (`harmonic_voice_set_hq(v, 1)`) подвоює вартість осцилятора +
  character та додає 13-тапний half-band FIR — очікуйте ~1.7× CPU на голос.
  Латентність +3 семпли (`Voice::HQ_LATENCY`).
- **`Waveform::Saw` / `Triangle`** — PolyBLEP / PolyBLAMP: ~6 / ~15 флопів на
  семпл, без стану, без тригонометрії. Вимірювано **90 / 77 M семплів/с** —
  дешевше за геометричну несучу. Не HQ (вже band-limited).
- **Тракт голосу `render_sample` — суто скалярний.** Batch-API
  (`geometric_partials_x4`, `cos4_turns`, `core::simd` за
  `--features portable-simd`) **не інтегрований** у `Voice`: `Svf` та
  `Character` — серійні рекурсивні фільтри, часовій векторизації не
  піддаються. Batch-шлях наразі корисний **лише для голого осцилятора /
  офлайн-рендеру**.
- **Не очікуйте векторних інструкцій у гарячому циклі `render_sample`** на
  вбудованій платформі. Просторова векторизація (N голосів паралельно, SoA)
  розглядається (`team-rfc-technical-audit.md §2`), але не реалізована.

## 5. Регламент C-ABI

```c
#include "harmonic_core.h"

size_t sz  = harmonic_voice_size();          /* 512 сьогодні — НЕ хардкодити */
size_t al  = harmonic_voice_align();         /* 8 */
void  *mem = /* ваша стратегія: арена / пул / стек, >= sz, вирівняно на al */;

int rc = harmonic_voice_init(mem, 48000.0);   /* 0 ok · 1/2 clamped · 3 defaulted · -1 null */
if (rc != 0) { /* хост подав непідтримувану SR — оберіть іншу або перевірте rc */ }
double sr = harmonic_voice_sample_rate(mem);  /* фактична частота (може ≠ запитаної) */
harmonic_voice_set_frequency(mem, 220.0);
harmonic_voice_set_rolloff(mem, 0.9);
harmonic_voice_set_hq(mem, 1);                /* опц.: 2× OS проти аліасингу character; +3 семпли */

float buf[2 * FRAMES];                        /* INTERLEAVED stereo: L R L R ... */
harmonic_voice_process(mem, buf, FRAMES);    /* в аудіо-callback */

/* деструктора немає — Voice це POD; звільніть свою пам'ять самі */
```

Повний перелік функцій — `05_API_REFERENCE.md §2`. Ключове:

- `harmonic_voice_process` пише **interleaved stereo `f32`**; буфер має
  вмістити `2·num_frames` елементів.
- Усі сеттери клампляться всередині; `NULL` → no-op.
- `harmonic_voice_reset` поважає `free_running` (у цьому режимі фаза не
  скидається).

### Захист від аномалій

- `rolloff` клампиться в `[10⁻³, 0.9995]` → знаменник геометричної суми
  `1 − 2r·c₁ + r² ≥ (1−r)² > 0`; ділення на нуль неможливе.
- `Svf`: `Q ≤ 32` (немає самозбудження), `cutoff ≤ 0.45·f_s` (прогин
  `tan(π f_c/f_s)` скінченний).
- **`sample_rate` поза `[8000, 768000]` Hz клампиться до найближчої межі**
  (нескінченне/NaN → 48000), а `harmonic_voice_init` **повертає код**
  (`1` clamped-low, `2` clamped-high, `3` defaulted). Перевіряйте цей код і
  читайте `harmonic_voice_sample_rate()` — за клампу висота й темп будуть
  зсунуті. Все одно валідуйте SR на своєму боці до ініціалізації.

### Потокобезпека

C-ABI **не потокобезпечний**. Не викликайте сеттери та
`harmonic_voice_process` одночасно з різних потоків без зовнішньої
синхронізації. `Voice` — plain data, без атоміків.

## 6. Збірка під ціль

```sh
rustup target add thumbv7em-none-eabihf        # напр. Cortex-M4F
cd harmonic_core
cargo build --no-default-features --release --target thumbv7em-none-eabihf
# → target/thumbv7em-none-eabihf/release/libharmonic_core.a
```

`crate-type = ["lib", "staticlib", "cdylib"]` — для лінкування в C беріть
**`staticlib`** (`.a`). Заголовок — `include/harmonic_core.h` (рукописний,
синхронний з `ffi.rs`; регенерувати через `cbindgen` за потреби).

Перевірити бітову ідентичність математики на ARM перед постачанням:
`scripts/cross-verify.sh` проганяє весь тестовий набір під QEMU на
`aarch64-unknown-linux-gnu` та `armv7-unknown-linux-gnueabihf` (VFP `f64`
тотожний Cortex-M4F) і звіряє хеш сигналу з x86-64 референсом.

`--features portable-simd` потребує **nightly** і не застосовний до
вбудованих таргетів без `core::simd`-підтримки — використовуйте дефолтну
збірку (авто-векторизація `[f64; 4]` + точний скалярний фолбек).

## 7. Що гарантовано / що ні

| Гарантовано | Не гарантовано (поки) |
|---|---|
| Нуль алокацій, нуль паніки, `panic = "abort"` | Bit-exactness виміряно на `aarch64` + `armv7-hf` (QEMU); Cortex-M **залізо**, `thumbv6m` (soft-float), RISC-V прогін — ще ні |
| Θ(log n) / Θ(1) вартість; ~20–22 M семпл/с (x86, скаляр) | SIMD у гарячому циклі `render_sample` — **скаляр** |
| Стійкість SVF (`Q≤32`, cutoff-кламп), no-div-by-zero | 4× оверсемплінг · оверсемплінг фільтра (є лише 2× для character) |
| SR клампиться зі статус-кодом (не тиха підміна) | Кламп-шлях SR у реальному хості не тестований |
| POD-макет, безпечне побітове копіювання / серіалізація | Валідація в живому DAW / `pluginval` (скрипт готовий) |
| 70 тестів + дрейф-стрес; біт-у-біт на `aarch64` + `armv7-hf` (QEMU) | Сертифікація (IEC 62304 тощо) — `no_std` + `panic=abort` + zero-alloc це **передумови**, не сертифікація; реальне залізо Cortex-M ще не прогонялось |
| Alias-free **чистий** осцилятор під Найквіста | Alias-free при активних `character`/FM — лише в **HQ mode** (2× OS); без нього навмисний «цифровий характер» |
