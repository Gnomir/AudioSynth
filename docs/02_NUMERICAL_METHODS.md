# 02 — Чисельні методи (`no_std`, без `libm`)

`core` не надає для `f64` жодної з функцій `sin`, `cos`, `tan`, `exp2`,
`floor`, `abs`, `sqrt` — вони всі в `std` (або в `libm`). `harmonic_core`
не залежить ні від чого: `Cargo.toml` не має секції `[dependencies]`. Уся
математика в `src/trig.rs` побудована з примітивів `+ − × ÷` та
`f64::{to_bits, from_bits}`.

Це критично для двох цілей: (1) `#![no_std]` без глобального алокатора для
MCU; (2) детермінізм — жодного платформного `libm`, чиї результати можуть
відрізнятися між таргетами.

---

## 1. Поліноміальні ядра (|φ| ≤ π/4)

### `cos_kernel(φ)`

Ряд Тейлора `cos` через `φ¹⁶`, схема Горнера, 8 членів, **plain-арифметика
без `mul_add`** (щоб не тягнути символ `fma` на таргетах без апаратного
FMA — Cortex-M4F тощо):

```rust
let u = φ*φ;
let p = 1.0/20_922_789_888_000.0;         // φ¹⁶ / 16!
let p = p*u + (-1.0/87_178_291_200.0);    // −φ¹⁴ / 14!
let p = p*u + (1.0/479_001_600.0);        //  φ¹² / 12!
let p = p*u + (-1.0/3_628_800.0);
let p = p*u + (1.0/40_320.0);
let p = p*u + (-1.0/720.0);
let p = p*u + (1.0/24.0);
let p = p*u + (-0.5);
p*u + 1.0
```

Похибка: **< 3 ULP** на `[−π/4, π/4]`.

### `sin_kernel(φ)`

Аналогічно, через `φ¹⁷`, потім `φ · p`. Похибка **< 2 ULP**.

### `cos_kernel_fast(φ)` / `sin_kernel_fast(φ)` — для модуляторів

4-членний Горнер (Тейлор через `φ⁶` / `φ⁷`). Похибка **< 5·10⁻⁶** (~16 біт).
Удвічі менше операцій, ніж у високоточних ядер. Публічний API:
`cos_turns_fast`, `sin_turns_fast`, `sin_cos_turns_fast` — використовуються
для **LFO** та **коефіцієнтів панорами рівної потужності**, де ULP-точність
несучої — марна робота. Несучий осцилятор і FM-модулятор лишаються на
високій точності.

Спільна логіка редукції аргументу винесена в `reduce_turns` — обидва
варіанти `cos_turns` викликають її, відрізняючись лише ядром.

## 2. Діапазонна редукція (домен обертів)

`cos_turns(turns)` для будь-якого дійсного `turns` (`|turns| < 2⁵¹`):

1. **Згорнути до `[−0.5, 0.5]`**: `t = turns − round_int(turns)`.
2. **Парність**: `a = |t| ∈ [0, 0.5]` (через бітову маску, не `f64::abs`).
3. **Згорнути `[0.25, 0.5] → [0, 0.25]`**: якщо `a > 0.25`, то
   `a ← 0.5 − a`, `sign ← −1` (бо `cos(2πa) = −cos(2π(0.5−a))`).
4. **Розбити на π/4** (`= 0.125` оберта):
   - `a ≤ 0.125` → `sign · cos_kernel(a · 2π)` (аргумент ≤ π/4);
   - `a > 0.125` → `sign · sin_kernel((0.25 − a) · 2π)`
     (бо `cos θ = sin(π/2 − θ)`, аргумент `(0.25 − a) · 2π ≤ π/4`).

Неперервність у точці `a = 0.125`: `cos_kernel(π/4) = sin_kernel(π/4) = √2/2`.

`sin_turns(t) = cos_turns(t − 0.25)`.
`sin_cos_turns(t) = (cos_turns(t − 0.25), cos_turns(t))`.

### `round_int(x)`

Заміна `f64::round`. Насичуваний каст `(x as i64) as f64` (обрізання до
нуля; `as` у Rust насичує при переповненні / NaN → 0), потім піврегулювання
`±1` за знаком дробової частини. Валідно для `|x| < 2⁵²`.

### `floor_f64(x)`

`(x as i64) as f64`, потім `−1`, якщо результат більший за `x` (від'ємні
нецілі). Валідно для `|x| < 2⁵²`.

### `fabs` (внутрішня)

`f64::from_bits(x.to_bits() & 0x7fff_ffff_ffff_ffff)` — скидання знакового
біта. `from_bits`/`to_bits` — `const fn` у `core`.

## 3. `exp2(x)` — `2ˣ`

Заміна `f64::exp2`. Використовується для: `midi_to_hz`, детюн унісону,
вібрато LFO, pitch bend, коефіцієнти decay/release ADSR, `Q` фільтра.

1. **Розбиття**: `x = ⌊x⌋ + f`, `f ∈ [0, 1)`.
2. **`2^⌊x⌋`** — прямою побудовою поля експоненти IEEE-754:
   `f64::from_bits(((e + 1023) as u64) << 52)`, де `e` клампиться в
   `[−1022, 1023]`.
3. **`2^f`** — 8-членний Горнер (степінь 7). Коефіцієнти — **Remez мінімакс**
   `2^f` на `f ∈ [0, 1]` (не ряд Тейлора; `examples/fit_coeffs.rs`), `c₀ = 1`
   точно:

```rust
let p =  8.568_020_029_104_6e-5;
let p = p*f + -8.581_653_953_827_3e-5;
let p = p*f +  1.665_468_533_058_2e-3;
let p = p*f +  9.388_897_452_886_6e-3;
let p = p*f +  5.558_374_723_244_2e-2;
let p = p*f +  0.240_214_375_664_654_1;
let p = p*f +  0.693_147_677_442_756_6;   // ≈ ln 2 (мінімакс злегка зсуває)
let p = p*f +  1.0;                        // → ціле x лишається точним
two_fl * p
```

Відносна похибка: **< 2.2·10⁻⁸** на `f ∈ [0, 1]` (×70 краще за попередній
Тейлор `1.5·10⁻⁶`) — `~3·10⁻⁵` цента, за межею вимірності.

---

## 4. `tan_turns` / `tan_turns_fast` — прогин фільтра

- **`tan_turns(turns)`** `= sin_turns / cos_turns` — загальна, `|turns| < 0.25`.
- **`tan_turns_fast(turns)`** — **єдине** що викликає `Svf::recompute_g`.
  Домен гарантовано `turns = f_c/(2 f_s) ∈ [~10⁻⁵, 0.225]` (`f_c ≤ 0.45 f_s`),
  тож без діапазонної редукції, без окремих sin/cos — **один `[3/2]` рац.
  мінімакс** на `[0, 0.23]`:

  $$\tan(2\pi t) \approx \frac{t\,(n_0 + n_1 u + n_2 u^2)}{1 + d_1 u + d_2 u^2},
    \qquad u = t^2$$

  Rel err `< 10⁻⁷`, `~4×` менше флопів за `tan_turns`. Повністю модульований
  `Svf`: `41 → 87 M семпл/с` (`2.1×`, `06_VERIFICATION.md §3`).

## 5. Branchless-варіант для векторизації

`cos_turns` містить гілки (`if a > 0.25`, розбиття на π/4), які блокують
авто-векторизацію. `cos_turns_branchless(x)` виконує ту саму математику
через **арифметичний select**:

- Округлення через магічну константу `1.5·2⁵²`:
  `t = x − ((x + MAGIC) − MAGIC)` (round-half-to-even, `|x| < 2⁵¹`).
- Індикатори замість `if`: `over = (a > 0.25) as u8 as f64` (`0.0` або `1.0`),
  далі `a += over·(0.5 − 2a)`, `sign = 1 − 2·over`.
- Обидва поліноми (`c` і `s`) обчислюються завжди, вибір —
  `sign·((1 − use_sin)·c + use_sin·s)`.

`cos4_turns([f64; 4])` — 4-широкий цикл над цим. LLVM опускає його в
`VFMADD` (x86-64) / `FMLA` (AArch64), а на таргетах без SIMD (Cortex-M) —
у коректний скалярний код з ідентичним результатом.

Точність branchless-варіанту vs `cos_turns`: у межах кількох ULP (інше
округлення на точних половинах — несуттєво для фази).

### Феатура `portable-simd` (nightly)

`--features portable-simd` вмикає `#![feature(portable_simd)]` та явний
шлях `core::simd::f64x4` у `kernel::geometric_partials_x4_simd`. Формула
`S_n` рахується на `f64x4`; косинус іде через скалярний branchless-ядро
полейнно (поверхня `Mask`/`select` у `core::simd` змінюється надто часто,
щоб її фіксувати). На stable недоступно — там працює авто-векторизований
`[f64; 4]`-варіант.

## 6. Верифікація точності

Усі ядра тестуються проти `std`-математики на щільних розгортках
(`trig::tests`):

| Функція | Еталон | Макс. виміряна похибка | Діапазон розгортки |
|---|---|---|---|
| `cos_turns` | `(t·τ).cos()` | `< 2·10⁻¹¹` абс. | `t ∈ [−37, 37]`, крок `1.31·10⁻³` |
| `sin_turns` | `(t·τ).sin()` | `< 2·10⁻¹¹` абс. | те саме |
| `exp2` | `x.exp2()` | `< 2.2·10⁻⁸` відн. (Remez мінімакс) | `x ∈ [−60, 60]`, крок `0.017` |
| `tan_turns_fast` | `(t·τ).tan()` | `< 2·10⁻⁷` відн. | `t ∈ [10⁻⁵, 0.225]` (домен SVF) |
| `floor_f64` | `x.floor()` | точно | набір крайових точок |
| кардинальні точки | — | `cos_turns(0)=1`, `cos_turns(0.25)=0`, `cos_turns(0.5)=−1`, `cos_turns(2.5)=−1` | — |

`cos4_turns` перевіряється транзитивно через
`kernel::batched_x4_matches_scalar` (батч vs скаляр, `n` до 1500).

## 7. Заборонені виклики (`no_std`-контракт)

У не-тестовому коді `harmonic_core` **немає жодного** з:
`f64::{sin, cos, tan, asin, acos, atan, exp, exp2, ln, log2, powf, powi,
sqrt, floor, ceil, round, trunc, mul_add}`,
жодного `unwrap`/`expect`/`panic!`, жодної алокації, жодного `Box`/`Vec`/
`String`. `grep` це підтверджує (`06_VERIFICATION.md §5`). Профіль релізу —
`panic = "abort"`.

**`abs`, `clamp`, `max`, `min` — НЕ заборонені.** Це не трансцендентні
функції — на rustc 1.97 усі чотири реалізовані в `core` (intrinsics `minnumf64`/
`maxnumf64` тощо, компілюються в одну апаратну інструкцію `MINSD`/`MAXSD`/
`ANDPD` тощо, без жодного символу `libm`). Перевірено емпірично: мінімальний
`#![no_std] #![no_main]` бінарник під `thumbv6m-none-eabi` (Cortex-M0, без
FPU — найсуворіший таргет) компілюється й лінкується з `.min()`/`.max()`/
`.clamp()`/`.abs()` без жодної незв'язаної символьної залежності; та сама
проба з `.sqrt()` не РЕЗОЛВИТЬСЯ взагалі (`E0599: no method named sqrt` —
метод просто відсутній без `std`), підтверджуючи, що решта списку вище
(транscendентні функції, `floor`/`round`/`trunc`, `mul_add`) дійсно
недоступна. Код і надалі використовує ручний `fabs` (бітове маскування
знаку) там, де він уже є — це не помилка, просто застаріла обережність,
міняти робочий протестований код заради цього не варто.
